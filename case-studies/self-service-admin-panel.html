Admin Panel for Onboarding & Configuration

Kriyadocs · Product Manager

01

Problem

Enterprise publishing customers have different journal workflows, user roles and configuration requirements. When onboarding and configuration depend heavily on manual setup and technical intervention, implementation takes longer and routine administrative changes create additional dependencies. The opportunity was to simplify onboarding through a centralized administration interface and greater self-service capability.

02

What I did

  • Identified operational friction: Examined onboarding and configuration tasks that created dependencies on implementation and technical teams.
  • Defined the product opportunity: Focused on enabling administrators to manage supported configurations through a centralized, user-friendly interface.
  • Structured the requirements: Translated customer and operational needs into product specifications covering administrative workflows, configuration options and controls.
  • Designed for self-service: Simplified routine configuration tasks so administrators could complete them with less assistance.
  • Balanced flexibility and scalability: Considered differing enterprise requirements while aiming to keep configuration consistent and maintainable across customers.
03

Results

  • Reduced customer onboarding time from 12 weeks to 8 weeks, a 33% reduction.
  • Improved admin self-service.
  • Reduced friction in routine administrative workflows and supported a more scalable onboarding experience.
